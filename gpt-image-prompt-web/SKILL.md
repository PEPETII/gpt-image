# GPT Image Web Prompt

## Scope

将中文或自然语言需求整理成适合 ChatGPT 网页端直接粘贴的英文提示词。本 skill 是独立包，只使用同目录下的 `resources/prompt-templates.md`，不要求读取仓库文件或访问网站。

只输出提示词、中文翻译和影响结果的关键假设。不执行图片生成，不输出代码、SDK 调用、接口字段、模型选择或参数表。

## Workflow

### 1. 识别模式

- 用户提到“网页、ChatGPT、复制、粘贴、网页版”时使用本 skill。
- 用户只说“帮我写图片提示词”而未指定接口时，也使用本 skill。
- 没有输入图片时按生成处理。
- 提到上传图、参考图、修改、移除、替换、换装或保持原图时按编辑处理。
- 明确要求 API、Python、SDK、代码、`images.generate` 或 `images.edit` 时交给 API 版本，不输出本 skill 的结果格式。
- 用户明确要求两个版本时，网页版与 API 版本分别生成，不把两种输出混在一个结果中。

### 2. 提取需求

提取并保留：

- 主体、数量、身份特征、动作和相互关系；
- 场景、环境、时间、地点、叙事目的和受众；
- 风格、媒介、材质、色彩、光线、情绪和真实程度；
- 构图、视角、景别、镜头感、主体位置和留白；
- 图片中的精确文字、语言、大小写、出现次数和排版位置；
- 每张参考图提供的对象、风格或结构；
- 必须改变、必须保持和禁止额外改变的内容。

保留用户给出的专有名词、品牌名、数字和文案，不擅自翻译或改写精确文字。只在明显影响结果的缺口处提问，例如编辑对象、人物身份、产品几何、精确文案或多图角色关系。

### 3. 选择内置方法

读取 `resources/prompt-templates.md` 中与任务最接近的一个场景，组合其方法要点和模板变量。需要多个方法时，以主要目标为主，最多叠加两个相邻方法，避免把互相冲突的风格和约束堆进一个提示词。

- 信息图、流程、教学图、幻灯片：优先使用结构、层级、箭头、标签和可读性约束。
- 写实、历史、广告、UI、Logo、漫画：优先使用场景目标、受众、构图和可观察的视觉细节。
- 编辑：先写唯一变化，再写保持项和禁止额外变化。
- 多图：给每张图编号并写明角色、来源和目标位置。
- 角色连续性：先建立角色锚点，再描述新场景；重复不可变的外观特征。

### 4. 编写英文提示词

按以下顺序组织复杂需求：

1. 目标画面和用途；
2. 主体、动作、环境和关键细节；
3. 构图、视角、光线、色彩、材质和视觉层级；
4. 图片文字，使用引号并注明 `EXACT, verbatim`、出现次数和清晰度；
5. 编辑保护或其他硬性限制。

简单需求使用自然段；信息图、广告、UI 和编辑任务可以使用 `Subject`、`Composition`、`Lighting`、`Text`、`Constraints` 等英文小标题。将“高级”“好看”“有氛围”等抽象词转换为材质、光线、色彩、姿态或构图等可观察描述。

### 5. 处理编辑和参考图

所有编辑提示词都必须明确以下三组内容：

```text
Change:
[Only the requested change]

Preserve:
[Identity, geometry, pose, framing, lighting, and other invariants]

Do not change:
[Everything outside the requested edit]
```

人物编辑默认锁定脸部、五官、肤色、体型、姿势、表情、发型、比例和身份。产品编辑默认锁定几何形状、材质、颜色、标签、文字和品牌识别特征。合成时说明每张图的角色，并要求统一光线、阴影、透视、比例和景深。用户没有要求的内容不得擅自重设计。

### 6. 返回结果

严格使用以下结构：

````markdown
## 网页版提示词

```text
[可直接复制到 ChatGPT 网页端的英文提示词]
```

## 中文翻译

[英文提示词的中文翻译]

## 关键假设

[仅列出影响生成结果的推断；没有时写“无”]
````

中文翻译必须与英文提示词逐项对应。关键假设只记录真正影响主体、构图、文字、身份、输入图角色或编辑范围的推断。用户要求迭代时，只修改指定维度，并重新输出完整可复制提示词。

## Quality rules

- 英文提示词必须可以脱离本 skill 独立理解。
- 精确文字逐字保留，不替用户编造品牌名、数字或标签。
- 编辑任务必须同时出现 Change、Preserve 和 Do not change 的语义。
- 多图任务必须使用稳定的 `Image 1`、`Image 2` 编号。
- 不把输出契约、内部路由或模板说明复制进英文提示词。
- 不承诺一次生成成功；需要迭代时只建议一次改变一个变量。
- 不承诺无法确认的能力，也不提供绕过安全限制的写法。
